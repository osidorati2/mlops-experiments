Наш сервис — **небольшое API для классификации изображений с сохранением истории результатов**. В будущем оно будет запускать настоящую ML-модель, а в LAB 02 используем простой предсказатель-заглушку.

Представь пользователя, который отправляет фотографию и получает ответ: «на изображении кот». Позже он может посмотреть историю предсказаний.

**Основной сценарий**

1. Пользователь отправляет изображение в API.
2. Сервис проверяет, что это действительно читаемое изображение. Пустой файл или произвольный текст должны приводить к понятной ошибке.
3. Передаёт изображение предсказателю.
4. Получает класс и версию модели.
5. Сохраняет сведения об изображении и результат в SQLite.
6. Возвращает ответ пользователю.

Например:

```json
{
  "image_id": 12,
  "prediction_id": 18,
  "class": "cat",
  "model_version": "stub-v1"
}
```

**Что делает заглушка**

Она имеет тот же смысловой интерфейс, что и будущая модель: **принимает изображение → возвращает класс и версию**. Пока она может всегда возвращать `cat` и `stub-v1`. Это не настоящее распознавание: мы проверяем работу сервиса вокруг модели.

Позже должна быть возможность заменить заглушку настоящей моделью, не переписывая обработку HTTP-запросов и сохранение истории.

**Какие возможности нужны**

| Возможность | Ожидаемое поведение |
|---|---|
| Проверка работоспособности | Сервис отвечает, что запущен |
| Предсказание для изображения | Проверяет файл, вызывает предсказатель, сохраняет результат и возвращает ответ |
| Просмотр истории | Возвращает сохранённые предсказания с именами изображений |

Для этой лабораторной не нужны авторизация, интерфейс сайта, обучение модели и отдельное хранилище фотографий. Сам файл можно обработать в памяти и не сохранять на диск.

**Что храним**

| Сущность | Данные |
|---|---|
| Изображение | ID, исходное имя файла |
| Предсказание | ID, ID изображения, класс, версия модели, время предсказания |

Одинаковое имя файла **не означает одно и то же изображение**. Для простоты каждый новый успешный запрос создаёт новую запись изображения и одно предсказание. Повторная отправка файла тоже создаёт новые записи.

Две таблицы нужны для учебной практики с SQL и позволяют в дальнейшем хранить несколько предсказаний для одного изображения. Изображения без предсказаний для упражнения с `LEFT JOIN` добавим в тестовые данные отдельно.

**Правила при ошибках**

- Некорректное изображение → ошибка ввода, предсказатель не вызывается, записи не создаются.
- Предсказатель сломался → ошибка сервиса, успешный результат не сохраняется.
- Сохранение в БД не удалось → ошибка сервиса. Успешный ответ возвращаем только после сохранения.
- Запись изображения и предсказания сохраняются вместе: если одна операция не удалась, откатываем обе.

**Теперь твоя задача — выделить ответственности:** кто принимает HTTP-запрос, кто проверяет изображение, кто выполняет сценарий, кто предсказывает и кто работает с БД. Необязательно делать отдельный файл или класс для каждой ответственности.
